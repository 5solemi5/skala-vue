# SKALA 오늘의 채비

> 같은 하늘, 다른 하루

**배포** : https://skala-vue-seven-alpha.vercel.app

---

## 이 서비스가 하는 일

날씨앱은 "내일 비 20mm"까지만 알려준다. 그다음은 각자 알아서 판단해야 한다.
그런데 같은 예보를 보고도 준비해야 하는 건 하는 일마다 다르다.

| 오늘 날씨 | 정비소 (자동차 정비) | 밭 (농사) |
|---|---|---|
| 습도 88% | 도장 걸면 백화가 생긴다 → 오늘은 미룬다 | 잎에 물기가 오래 남는다 → 곰팡이병 조심 |
| 최저 2℃ | 배터리 방전 출동이 몰린다 → 재고 확인 | 서리 위험 → 오늘 밤 피복하거나 수확을 앞당김 |

| 오늘 날씨 | 출퇴근길 (자전거) | 주말 경기 (야구) |
|---|---|---|
| 강수확률 70% | 노면이 젖으면 제동 거리가 늘어난다 → 두고 간다 | 우천 취소 가능성 → 표를 미리 정리한다 |
| 풍속 8m/s | 옆바람에 중심을 잃는다 → 오늘은 아니다 | 뜬공 판단이 어려운 날 |

챙길 수 있는 일은 일곱 가지다.
**자동차 정비소 · 농사 · 현장 작업 · 자전거 · 등산 · 야구 · 빨래·환기**

같은 숫자를 하는 일에 맞춰 다르게 읽어주는 게 이 서비스다.

**왜 만들었나** — 가까운 분들 중에 날씨로 하루가 달라지는 일을 하시는 분들이 있다.
두 분 다 아침마다 날씨를 확인하시는데 어느 앱도 "그래서 오늘 뭘 하시라"는 말은 안 해준다.
매일 전화로 물어볼 수도 없어서 대신 봐 주는 화면을 만들기로 했다.

만들다 보니 날씨로 하루가 바뀌는 사람이 두 분만은 아니었다.
자전거를 타는 나도, 주말에 야구를 보러 가는 것도 마찬가지였다.
그래서 챙길 대상을 넷으로 늘렸다.

## 기능 정리

**1. 챙길 곳 등록하기**
이름(예: 정비소, 밭, 출퇴근길)과 하는 일, 지역을 넣어 **열두 개까지** 등록한다.
대상마다 지역이 따로라서 멀리 떨어진 곳도 함께 볼 수 있다.
등록한 목록은 저장돼서 다음에 들어와도 그대로다.

**2. 오늘, 내 사람들**
화면 맨 위에 등록한 곳이 한 줄로 나온다.
각자 **자기 지역 날씨**와 **자기 기준 판정**이 함께 표시된다.
아침에 한 번 열면 챙길 곳들이 한눈에 들어온다.

**3. 오늘의 채비**
카드를 누르면 그 곳이 화면 위쪽에 크게 나온다.

- 기온, 날씨, 습도, 강수확률
- 판정 — `오늘은 아니에요` / `조심하세요` / `괜찮아요` 중 가장 무거운 것을 앞세우고 나머지는 아래에
- 왜 그런 판정인지 근거를 함께 표시 (`습도 88% — 도막에 수분이 물려 백화가 생깁니다`)
- 시간대별 막대 — 앞으로 18시간을 색으로 표시하고 괜찮은 구간을 찾아 알려준다

**4. 다른 지역 목록**
목록 위 한 줄로 전체 상황이 먼저 읽힌다 (`7곳 중 4곳은 오늘 피하시는 편이 낫습니다`).
행을 누르면 위쪽 화면이 그 지역으로 바뀌고, `상세`를 누르면 상세 화면으로 간다.

**5. 지역 검색**
한글로 검색되고 동명이지는 지역명으로 구분해 보여준다 (`광주` → 광주광역시 / 경기 광주시).
지오코딩 API 두 곳을 함께 검색해서 한쪽에만 있는 지역(철원, 영월 등)도 찾을 수 있다.

**6. 상세 화면** `/weather/:cityId`
관측값 여섯 가지와 시간대별 막대, 그리고 일곱 가지 일을 나란히 비교.
같은 날씨가 정비에는 `조심하세요`, 자전거에는 `괜찮아요` 인 것을 한눈에 볼 수 있다.

**7. 단위 전환**
헤더의 ℃ / ℉ 토글. 메인·목록·상세·시간대 막대에 한꺼번에 반영되고 저장된다.
판정 근거 문장의 기온도 같이 바뀐다. 화씨로 보는데 근거만 섭씨면 앞뒤가 안 맞는다.

**8. 한국어 / English**
같은 자리의 `한` / `EN` 토글. 화면 문구와 판정 문구 전부가 바뀐다.
날씨 설명(`튼구름` / `broken clouds`)은 API 가 언어에 맞춰 주는 값이라
언어를 바꾸면 날씨를 다시 받아 온다. 선택한 언어는 저장된다.

**9. 지금 있는 곳의 날씨**
헤더의 `내 위치`. 누르면 브라우저 위치를 받아 그 지역 이름과 기온을 띄우고,
한 번 더 누르면 그곳의 오늘의 채비가 메인에 펼쳐진다.

들어오자마자 위치를 묻지 않는다. 무슨 사이트인지 알기도 전에 권한 팝업이 뜨면
일단 거절하게 되고, 한 번 거절하면 브라우저 설정을 열기 전까지 되돌릴 수 없다.
이미 허용해 둔 브라우저에서만 Permissions API 로 확인한 뒤 조용히 불러온다.
거절은 다시 조르지 않고 물러나고, 시간 초과처럼 다시 될 수 있는 실패만 재시도를 열어 둔다.

**10. 챙기는 사람들이 노는 마당**
`오늘, 내 사람들` 아래 작은 무대. 챙기는 사람 수만큼 캐릭터가 걸어다닌다.
사람을 더하거나 지우면 마당 인원도 같이 늘고 준다.
배경은 들판·바닷가·밤하늘·눈밭·골목 다섯 가지이고 고른 것은 저장된다.

## 만들면서 정한 것

**색은 판정에만 쓴다.**
브랜드 색을 따로 두면 화면에 색이 두 종류로 섞여서, 색이 보여도 그게 서비스 색인지
주의하라는 뜻인지 알 수 없다. 기본은 무채색(짙은 남색 잉크 + 차가운 회청 지면)으로 두고
색은 판정 세 가지에만 썼다. 화면에서 색이 보이는 곳 = 신경 쓸 곳.

**문구는 규칙에서 떼어 냈다.**
처음에는 판정 규칙 파일에 조건과 문장이 같이 있었다. 언어가 둘이 되니
규칙 하나에 문장이 둘씩 붙어서 조건이 안 보였다. 규칙은 어떤 문구인지 키만 넘기고
문장은 언어 파일에서 찾아 쓰게 했다.

**판정은 아이콘이 아니라 글자로.**
아이콘만으로는 "하지 마세요"와 "조심하세요"가 구분되지 않는다. 테두리 친 글자로 표시했다.

**결정 순서대로 배치했다.**
처음에는 검색 / 내 지역 / 모드 / 목록이 전부 같은 크기의 상자로 쌓여 있었다.
무엇부터 봐야 하는지 알 수 없어서, 실제 판단 순서인
`어디를 챙기나 → 그래서 뭘 해야 하나 → 다른 지역은 어떤가` 로 다시 세웠다.

**열두 개까지만 등록할 수 있게 했다.**
아침에 한 번 훑어보는 화면이라 한눈에 들어오는 만큼만 둔다.
처음엔 여덟 개로 잡았는데 네 개씩 세 줄이 화면 안에 그대로 들어와서 열둘로 늘렸다.
더 늘리면 카드가 작아지고 결국 스크롤하게 되는데, 그러면 한눈에 본다는 목적이 사라진다.

**마당은 판 아래에 뒀다.**
캐릭터를 놓을 자리를 네 군데 놓아 봤다.
화면 전체 배경에 깔았더니 판정을 읽는 내내 시야 구석에서 뭔가 움직여 방해가 됐다.
제목 옆은 버튼과의 사이가 좁아 열두 명이 비좁았고, 제목과 버튼이 갈라져 보였다.
판 위에 두니 제목과 표 사이가 벌어져서 제목 바로 밑에 정보가 아니라 장식이 먼저 왔다.
판 아래여야 제목이 자기 표에 붙어 있고 읽는 순서도 그대로다.

**색은 판정에만 — 마당은 예외로 뒀다.**
마당의 무대와 옷 색은 화면에서 유일하게 색을 마음껏 쓴 곳이다.
대신 판정에 쓰는 빨강·주황·초록과는 겹치지 않는 색만 골랐다.
마당이 화사해도 "색이 보이면 신경 쓸 곳" 이라는 규칙은 깨지지 않는다.

**로고**
세 획이 같은 높이에서 시작하고 아래쪽 색이 차오른 만큼이 판정의 무게다.
같은 하늘을 보지만 하루가 달라진다는 서비스의 말을 그대로 형태로 옮겼다.

## 화면

| 경로               | 설명                                    |
| ------------------ | --------------------------------------- |
| `/`                | 지역별 날씨 + 모드별 오늘의 채비        |
| `/weather/:cityId` | 지역 상세 (일곱 가지 일을 한 번에 비교)|
| `/about`           | 서비스 소개                             |
| `/lab`             | 수업 Code Challenge 결과물 모음         |

## 실행

```sh
npm install
npm run dev      # http://localhost:5173
npm run lint
npm run build
```

OpenWeatherMap 키가 필요하다. 루트에 `.env.local` 을 만들고 넣는다.

```
VITE_OPENWEATHER_API_KEY=발급받은키
```

## 배포

Vercel 에 올렸다. `main` 에 푸시하면 자동으로 다시 빌드된다.

배포하면서 두 가지를 맞춰야 했다.

**하위 주소가 404 날 것 같아서 미리 막았다.**
라우터를 history 모드로 만들었으니 주소창에 `/dev-log` 를 직접 치면 브라우저가
서버에 그 경로를 그대로 요청한다. 서버에는 그런 파일이 없다. 개발 서버는 못 찾으면
`index.html` 을 돌려주도록 되어 있어서 로컬에서는 드러나지 않는 문제였다.
올리기 전에 `vercel.json` 에 규칙을 넣어 두고, 배포 후 다섯 경로를 직접 확인했다.

```json
{ "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }] }
```

**환경변수는 빌드 전에 넣어야 한다.**
`import.meta.env.VITE_...` 는 실행 중에 읽는 값이 아니라 빌드할 때 문자열로
바뀌어 들어간다. 배포한 다음에 키를 등록하면 이미 만들어진 번들에는 반영되지
않아서 다시 빌드해야 한다.

그래서 키가 결과물 안에 그대로 들어간다. 개발자 도구로 보면 찾을 수 있다.
`VITE_` 를 붙인 값은 전부 공개된다고 보는 게 맞고, 감춰야 하는 키라면
서버를 하나 두고 거기서 부르는 게 맞다. 이번엔 무료 플랜 날씨 키라 그대로 뒀다.

## 사용한 것

Vue 3 (Composition API) · Vue Router · Pinia · Axios · Vite
Tailwind CSS v4 + shadcn-vue · Element Plus

API 는 두 곳을 쓴다.

- **OpenWeatherMap** — 현재 기온, 날씨 상태, 습도, 풍속, 아이콘
- **Open-Meteo** — 오늘 최저기온, 강수확률 (키 불필요)

OpenWeatherMap 무료 플랜에 오늘 강수확률과 일 최저기온이 없다.
그게 없으면 방제·서리 판정을 못 해서 Open-Meteo 를 같이 부른다.

## 폴더

```
src/
├── api/weatherApi.js       두 API 를 합쳐 화면이 쓸 형태로 만든다
├── locales/                화면·판정 문구 (ko / en)
├── utils/
│   ├── adviceRules.js      하는 일별 판정 규칙 (조건만, 문장은 locales)
│   ├── weatherCondition.js 날씨 상태 코드 (판정에 쓰는 값)
│   └── hourlyScore.js      시간대별 판정 (위 규칙을 그대로 재사용)
├── stores/
│   ├── configStore.js      단위(℃/℉), 하는 일, 언어, 마당 배경
│   ├── cityStore.js        내 지역 목록
│   ├── peopleStore.js      챙기는 사람들
│   └── hereStore.js        지금 있는 곳의 날씨
├── components/
│   ├── service/            지금 서비스 화면을 이루는 컴포넌트
│   ├── exercise/           과제 단계별 결과물 (아카이브에서 그대로 사용)
│   ├── practices/          수업 Code Challenge 실습 (수업 때 쓴 그대로 둠)
│   └── ui/                 shadcn-vue 컴포넌트
└── views/
```

`practices/` 와 `exercise/` 는 수업·과제 시점의 코드를 유지했다.
지금 화면은 `service/` 아래 컴포넌트로 다시 짰다.

## 과제 대응표

| 과제           | 파일                       | 개인 추가분                                         |
| -------------- | -------------------------- | --------------------------------------------------- |
| 2. Mockup      | `WeatherMockup.vue`        | 도시 3개, 습도·강수확률·최저기온, 모드 4종          |
| 3. Composition | `WeatherComposition.vue`   | `adviceMap` / `alertCityCount` computed, 모드 watch |
| 4. Component   | `WeatherParent.vue` 외 5개 | `ModeSelector` / `AdviceList` 추가 분리             |
| 5. Router      | `views/`                   | `/lab` `/archive` `/dev-log` 추가                   |
| 6. Store       | `configStore.js`           | 모드·언어·배경 state·getter·action, `convertTemp`   |
| 7. Axios       | `api/weatherApi.js`        | Open-Meteo 추가                                     |
| 8. UI Library  | 전역                       | Tailwind + shadcn-vue 선정                          |
| 9. 배포        | `vercel.json`              | SPA rewrite, 빌드 시점 환경변수 주입                |

교재 범위를 벗어나는 라이브러리는 쓰지 않았다.
한/영 전환은 `vue-i18n` 없이 스토어 값 하나와 문구를 찾아 주는 함수로 만들었고,
위치 날씨는 브라우저의 `navigator.geolocation` 과 이미 있던 `fetchCityWeather` 를 그대로 썼다.
마당도 SVG 와 CSS 애니메이션뿐이다.
